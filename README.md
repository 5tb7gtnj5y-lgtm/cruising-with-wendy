# Cruising with Wendy — your Cloudflare version

Prepared 13 October 2026. This is a separate build; it does not change the current ChatGPT Site. It runs on your Cloudflare Workers account at a workers.dev address, with a D1 database. No custom domain is required.

## What is ready

- The current cruise UI, expanding news feed, real-photo assets, filters and compact shopping strips.
- A private backup of all 31 content records (28 news, two original articles and one guide), settings, history and view counts. Full article text is included. No account tokens are included.
- Your own administrator password login with an eight-hour secure session, sign-out, hashed session tokens, CSRF checks and login attempt limiting. ChatGPT identity headers grant no access here.
- A three-hour Cloudflare Cron Trigger that checks the ten approved primary newsrooms. It places recent, dated announcement metadata in the news review queue. Missing dates, blocked sources and unreadable pages are skipped; source failures are recorded without deleting saved stories. Duplicate and archived URLs stay suppressed. Pause applies to collection.
- The protected researched-update API, including the limit of one original AI-assisted draft per UTC day. Original drafts stay unpublished for administrator approval.

The Cron Trigger does **not** write original AI articles or fact-check newsroom metadata. The existing ChatGPT researcher still targets the old Site. Reconnect a researcher to the new API after the destination is verified, then retire the old update connection. An AI API key/provider is not configured in this package, and no paid AI service has been enabled.

## First setup

1. Install Node.js 22.13 or newer and pnpm 11.25.0. Extract this ZIP into its own folder.
2. Run `pnpm install --frozen-lockfile` and `npm run check`, then `npm run typecheck`.
3. In your Cloudflare dashboard, register/find your Workers subdomain. Your URL will be `https://cruising-with-wendy.YOUR-SUBDOMAIN.workers.dev`.
4. Run `npm run setup` in an interactive terminal. It opens Cloudflare's normal sign-in, selects your account, asks for the exact destination URL, creates a new D1 database, applies migrations, imports the backup and reads every saved row back for comparison. It asks for your new admin password with hidden input and stores only the password hash and a new update token as Cloudflare Worker secrets.
5. Open the deployed `/admin/login`, sign in, and check the saved content. Test sign-out and confirm that private pages require sign-in. Confirm a scheduled collector run in Cloudflare Worker logs. Validated, dated news links publish automatically; original articles and guides require approval. Some primary sites block automated access; the collector reports these honestly and preserves saved data.

The initial deployment is **private**, matching the existing Site. If you choose to launch publicly later, set `ACCESS_MODE` to `public` and `SITE_PUBLIC` to `true` in `wrangler.jsonc`, then run `npm run deploy`. Administrator and service API routes remain protected.

Setup never overwrites a populated nonmatching database. Re-running setup resets the admin password and update token; reconnect any external researcher after that reset. Do not run setup during normal updates. Use `npm run deploy` instead.

## GitHub and continuing deployment

Create a new **private** repository named `cruising-with-wendy`. Upload/commit this source after setup has filled the real account/database/origin values. Keep `transfer-data/`, `.dev.vars*`, `.env*`, `node_modules`, `.wrangler` and `dist` out of GitHub; `.gitignore` excludes them. The transfer backup contains site history and belongs with your private backups.

In Cloudflare Workers & Pages, connect that repository through Workers Builds. Use build command `pnpm install --frozen-lockfile && npm run build`, and deploy command `npx wrangler deploy --config dist/server/wrangler.json`. Keep `ADMIN_PASSWORD_HASH` and `UPDATE_TOKEN` as runtime secrets in Cloudflare, never as committed files or client variables. A normal deployment preserves D1 data; apply future D1 migrations deliberately.

## Automatic news links

The Worker checks the approved primary newsrooms every three hours and publishes dated news links automatically. Homepage and news visits catch up an overdue check in the background. Duplicate links, archived suppressions and administrator-edited drafts are preserved. Only untouched old collector news drafts can be published after their source is revalidated. Pause stops both collection and researched imports. Fetches are bounded and publication uses a single guarded database statement per link. Failed sources leave existing content in place.

## Researched automatic updates

Use the new deployment's own `UPDATE_TOKEN` in `X-Update-Token`. Never send a ChatGPT Sites bearer credential to this Cloudflare endpoint. The token generated by setup is stored only in Cloudflare; it is not printed or written to this package. Configure any external researcher using a separately managed secret that matches the Worker's `UPDATE_TOKEN`, through a secure secret manager rather than chat or source code.

Read `/api/system/instructions` and `/api/system/state`, respect pause, research approved primary sources, POST verified new links and an optional original draft to `/api/system/sync`, then read back `/api/system/state`. The API preserves daily limits, duplicate checks, suppression and review-only original drafts. Disable the old connection only after the new destination and researcher have passed these checks. See `UPDATE_INSTRUCTIONS.md`.

## Backup and rollback

Keep the current Site running during cutover. This ZIP's `transfer-data/site-backup.sql` is for a new empty database, not an in-place restoration over live content. Before future changes, take an administrator export and a D1 backup. If the new deployment fails, continue using the current Site; do not change its access settings or rotate its credentials to work around the failure.
